# 資金の保管と保護

Signaウォレットの識別、オンチェーン送金、口座残高、取引ポジション、出金確認をチェック可能な記録された資金経路に結びつけます。これらの管理により、住所ミス、重複支払い、確認前クレジット、不正な引き出しなどのリスクが軽減されます。

## 6つの保護機構

1. **専用入金アドレス：** アカウントごとに異なるBSCアドレスを使い、資金の帰属を識別します。
2. **ネットワークと資産の検証：** BSC Chain ID 56と指定されたBinance-Peg USDTコントラクトのみを認識します。
3. **確認後の残高反映：** オンチェーン送金を検証し、必要な確認数に達した後に利用可能残高へ反映します。
4. **入出金の分離管理：** 入金回収と出金送付を異なる管理経路に分け、単一障害点の影響を抑えます。
5. **照合可能な台帳：** 入金、取引、手数料、ポジション、出金をアカウント記録として残します。
6. **出金時の再署名：** 金額、手数料、送付先、ワンタイム認証を再確認し、アカウントに対応するウォレットへだけ返送します。

これらの仕組みは資金の状態をより明確かつ追跡可能にし、多層的な保護を提供します。どの技術的・保管システムも絶対的な安全を約束したり、入金保険やリスクフリーの保証として扱われたりすることはできません。

## ウォレット署名は何をするものなのでしょうか?

- サインイン署名はBSCウォレットの管理権を証明します。
- 出金署名は宛先、金額、手数料、有効期限、そして無条件を確認します。
- 通常の署名で、秘密鍵やシードフレーズがSignaへ渡ることはありません。

Signaドキュメントやサポートチャット、フォームで秘密鍵やシードフレーズを求めることは決してありません。

## 資金は実際にどこに保管されているのでしょうか?

USDTが専用のアドレスに送信され確認されると、ユーザーの個人ウォレットに保管されるのではなく、Signaが保管します。製品に表示されている利用可能な残高や指数持分は、ウォレット内のオンチェーントークン残高ではなく、Signa口座の元帳記録です。

引き出しの場合は、ユーザーがリクエストに署名します。口座、残高、手数料、宛先の確認の後、引き出し可能なUSDTはサインインしたウォレットに返送されます。これはカストディアル製品であり、すべての取引がユーザーのウォレットに直接決済されるエンドツーエンドのセルフカストディモデルではありません。

## 取引や口座はどのように管理されているのでしょうか?

- サーバーは購入前に価格、手数料、インデックスバージョン、有効性をロックします。
- 利用可能な残高、指数持分、限度額は注文時に再度確認されます。
- 資金、手数料、ポジション、出金は照合可能な元帳のエントリーを使用します。
- 指数価格が古くなっている、欠落している、または検証不能であれば、新規取引はクローズ失敗となります。
- 入金、出金、取引履歴は照合のために引き続き利用可能です。

## どのようなリスクが残っていますか？

### 市場および流動性

薄い市場、広いスプレッド、速報、または小規模な取引により、イベント価格が急速に動き、指数に影響を与える可能性があります。

### モデルおよびデータ

方向、影響、情報の重複が誤判断される可能性があります。データは遅延、中断、または修正されることがあります。

### ブロックチェーンおよびカストディ

BSCの混雑、再編成、RPCの障害、トークン契約の問題、署名キーのリスク、またはカストディサービスの失敗により、資金の運用が遅延または影響を受ける可能性があります。

### 製品の可用性

取引、出金、または新しい入金アドレスの割り当てが一時停止または遅延する場合があります。チェーン上の結果が不確定な出金は、ページタイムアウト後に予約金額を即座に返却するのではなく、保留状態のまま残ります。

### 法務、税務、および地域

適格性、税務処理、合法性は場所や状況によります。1%の購入手数料は製品に対する料金であり、個人の税務義務に関する判断ではありません。

::: danger リスクの境界
署名、複数のチェック、分離された管理、確認、および台帳の照合は特定の失敗を減らしますが、資金、可用性、元本、またはリターンを保証するものではありません。
:::
