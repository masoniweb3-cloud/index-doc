# データソース

基準価格の入力は、観測可能な実際のイベント契約市場から取得されます。ソースは安定した収集、過去の再現、および明確なタイムスタンプをサポートする必要があります。

## 必要な記録

各候補契約について、少なくとも次のことを記録します:

- 市場および契約の識別子;
- 元の提案および結果オプション;
- 決済条件、締め切り、およびステータス;
- 価格およびタイムスタンプ;
- 利用可能な取引、流動性、またはスプレッド情報;
- ソースおよび収集バージョン;
- 後からの修正、無効化、または決済記録。

## 価格の選択

公開された方法論は、実行可能な中央値価格、最終取引、時間加重平均価格、または他の検証済みの参照価格など、価格の種類を定義します。

選択は、孤立した取引、一時的なスプレッド拡大、または単一ポイントの異常の影響を減らしつつ、再現可能であるべきです。

## 時間の一貫性

市場は更新時間、タイムゾーン、および中断が異なります。計算は1つの時間基準と、締切、欠損データ、および遅延に関する明示的なルールを使用します。

## 複数のソース

同じイベントが複数の市場で取引される場合があります。ルールは、価格を結合するか、主要市場を選択するか、ソースの優先順位を使用するかを事前に定義する必要があります。ソースの変更は記録され、履歴を黙って書き換えることはありません。
