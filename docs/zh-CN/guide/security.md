# 资金安全与风险

Signa 将资金安全贯穿于钱包登录、充值确认、资金托管、交易记账和提现验证的完整链路。每一步都需要匹配明确的账户、网络、资产、金额和状态，不依赖单一的页面提示或链上交易状态。

## 六层资金保护

1. **专属地址**：不同账户使用不同的 BSC 充值地址，降低充值归属错误。
2. **资产白名单**：仅识别 BSC Chain ID 56 和指定的 Binance-Peg USDT 合约。
3. **确认后入账**：交易必须通过 Transfer、回执、区块和确认数校验，才会增加可用余额。
4. **隔离托管**：充值归集与提现支付使用隔离的服务、密钥、账户和访问凭据。
5. **可对账账本**：充值、交易、费用、持仓和提现都以平衡账本记录。
6. **提现再验证**：提现地址锁定为账户对应钱包，金额、手续费和一次性随机数需要重新签名确认。

## 你的钱包签名在做什么？

- 登录签名用于证明你控制该 BSC 钱包；
- 提现签名用于确认目标钱包、金额、手续费、有效期和一次性随机数；
- 正常签名不会让 Signa 获得你的私钥或种子词。

Signa 不会要求你在文档、客服聊天或表单中提交私钥或助记词。

## 充值和提现如何受控？

当前实现包括：

- 为不同账户分配独立的 BSC 充值地址；
- 仅接受 BSC Chain ID 56 和指定的 Binance-Peg USDT 合约；
- 校验 Transfer 事件、区块确认数、区块归属和最终性；
- 将充值归集和提现支付放在隔离的托管服务中；
- 充值归集和提现使用分离的密钥、账户和访问凭据；
- 在操作重试时复用同一请求和交易身份，避免因网络超时创建第二笔支付；

## 交易和账本如何受控？

- 买入前由服务端锁定价格、费用、指数版本和有效期；
- 下单时重新校验可用余额、持仓份额和订单限额；
- 交易资金、费用、持仓和提现使用可对账的账本分录；
- 指数价格过时、缺失或无法验证时，新交易应失败关闭；
- 充值、提现和交易状态保留用户可查记录，便于核对资金路径。

## 安全托管方式

用户将 USDT 充值到专属地址后，资金会进入 Signa 统一托管体系。专属地址负责准确识别账户与充值；达到确认要求后，对应金额记入用户的可用余额，并由隔离的托管服务统一管理链上资金。

交易期间，可用余额和持仓由可对账账本记录；提现时，系统再次验证账户、钱包、金额和签名后，将 USDT 发送回对应的 BSC 钱包。这是托管型产品，而不是每笔交易都直接在用户钱包中结算的全程自托管模式。

## 安全机制不能消除哪些风险？

### 市场和流动性风险

预测市场可能因流动性不足、价差扩大、突发消息或少量交易而快速变动，进而影响指数。

### 模型和数据风险

事件与目标状态的方向、影响强度或信息重叠可能被误判；数据源也可能延迟、中断或更正。

### 区块链与托管风险

BSC 拥堵、链重组、RPC 中断、代币合约问题、签名密钥风险或托管服务故障，都可能延迟或影响充提。

### 产品可用性风险

交易、提现或新充值地址分配可能在异常时被暂停或延迟。

### 法律、税务与地区风险

可参与性、税务处理和产品法律性取决于所在地和个人情况。文档中的“1% 开仓费”是产品收费，不是对个人税务义务的判断。

::: danger 风险边界
钱包签名、多层校验、密钥隔离、确认数和账本对账只能降低特定故障的概率或影响，不代表资金、交易可用性、本金或收益获得保证。
:::
