# 资金如何保管与保护

Signa 采用多重资金保护机制，将钱包身份、链上转账、账户余额、交易持仓和提现验证连接成一条可校验、可记录的资金路径。这些机制用于降低地址错误、重复支付、未确认入账和未经授权提现等风险。

## 六项资金保护机制

1. **专属充值地址**：不同账户使用不同的 BSC 地址，帮助系统准确识别资金归属。
2. **网络和资产校验**：仅识别 BSC Chain ID 56 和页面指定的 Binance-Peg USDT 合约。
3. **确认后入账**：系统核对链上转账并达到所需确认数后，才增加可用余额。
4. **充提分离控制**：充值归集和提现支付采用相互分离的资金控制路径，减少单点故障影响。
5. **可对账账本**：充值、交易、费用、持仓和提现均形成账户记录，方便核对资金变化。
6. **提现再次签名**：提现只发回账户对应的钱包，并重新确认金额、手续费、地址和一次性授权。

这些设计让资金状态更加清晰、可追踪，并为正常充提提供多层保护。但任何技术和托管机制都无法承诺绝对安全，也不应被理解为银行存款保险或无风险保证。

## 你的钱包签名在做什么？

- 登录签名用于证明你控制该 BSC 钱包；
- 提现签名用于确认目标钱包、金额、手续费、有效期和一次性随机数；
- 正常签名不会让 Signa 获得你的私钥或种子词。

Signa 不会要求你在文档、客服聊天或表单中提交私钥或助记词。

## 资金实际放在哪里？

用户把 USDT 充值到专属地址并完成确认后，资金由 Signa 托管，不再保存在用户的个人钱包中。页面显示的可用余额和指数份额，是 Signa 账户账本中的余额与持仓记录，而不是钱包中的链上代币余额。

提现时，用户通过钱包签名确认申请。系统核对账户、余额、费用和目标地址后，再把可提现 USDT 发送回登录钱包。这是托管型产品，不是每笔交易都直接在用户钱包中结算的全程自托管模式。

## 交易和账户如何受控？

- 买入前由服务端锁定价格、费用、指数版本和有效期；
- 下单时重新校验可用余额、持仓份额和订单限额；
- 交易资金、费用、持仓和提现使用可对账的账本分录；
- 指数价格过时、缺失或无法验证时，新交易应失败关闭；
- 充值、提现和交易状态保留用户可查记录，便于核对资金路径。

## 安全机制不能消除哪些风险？

### 市场和流动性风险

预测市场可能因流动性不足、价差扩大、突发消息或少量交易而快速变动，进而影响指数。

### 模型和数据风险

事件与目标状态的方向、影响强度或信息重叠可能被误判；数据源也可能延迟、中断或更正。

### 区块链与托管风险

BSC 拥堵、链重组、RPC 中断、代币合约问题、签名密钥风险或托管服务故障，都可能延迟或影响充提。

### 产品可用性风险

交易、提现或新充值地址分配可能在异常时被暂停或延迟。处于链上结果不明确状态的提现会继续等待确认，不会仅因页面超时立即退回预留余额。

### 法律、税务与地区风险

可参与性、税务处理和产品法律性取决于所在地和个人情况。文档中的“1% 开仓费”是产品收费，不是对个人税务义务的判断。
