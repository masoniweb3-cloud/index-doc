# 資金如何保管與保護

Signa 採用多重資金保護機制，將錢包身份、鏈上轉賬、帳戶餘額、交易持倉和提現驗證連接成一條可校驗、可記錄的資金路徑。這些機制用於降低地址錯誤、重複支付、未確認入賬和未經授權提現等風險。

## 六項資金保護機制

1. **專屬充值地址**：不同帳戶使用不同的 BSC 地址，幫助系統準確識別資金歸屬。
2. **網路和資產校驗**：僅識別 BSC Chain ID 56 和頁面指定的 Binance-Peg USDT 合約。
3. **確認後入賬**：系統核對鏈上轉賬並達到所需確認數後，才增加可用餘額。
4. **充提分離控制**：充值歸集和提現支付採用相互分離的資金控制路徑，減少單點故障影響。
5. **可對賬帳本**：充值、交易、費用、持倉和提現均形成帳戶記錄，方便核對資金變化。
6. **提現再次簽名**：提現只發回帳戶對應的錢包，並重新確認金額、手續費、地址和一次性授權。

這些設計讓資金狀態更加清晰、可追蹤，並為正常充提提供多層保護。但任何技術和托管機制都無法承諾絕對安全，也不應被理解為銀行存款保險或無風險保證。

## 你的錢包簽名在做什麼？

- 登入簽名用於證明你控制該 BSC 錢包；
- 提現簽名用於確認目標錢包、金額、手續費、有效期和一次性隨機數；
- 正常簽名不會讓 Signa 獲得你的私鑰或種子詞。

Signa 不會要求你在文檔、客服聊天或表單中提交私鑰或助記詞。

## 資金實際放在哪裡？

使用者把 USDT 充值到專屬地址並完成確認後，資金由 Signa 托管，不再保存在使用者的個人錢包中。頁面顯示的可用餘額和指數份額，是 Signa 帳戶帳本中的餘額與持倉記錄，而不是錢包中的鏈上代幣餘額。

提現時，使用者通過錢包簽名確認申請。系統核對帳戶、餘額、費用和目標地址後，再把可提現 USDT 發送回登入錢包。這是托管型產品，不是每筆交易都直接在使用者錢包中結算的全程自托管模式。

## 交易和帳戶如何受控？

- 買入前由服務端鎖定價格、費用、指數版本和有效期；
- 下單時重新校驗可用餘額、持倉份額和訂單限額；
- 交易資金、費用、持倉和提現使用可對賬的帳本分錄；
- 指數價格過時、缺失或無法驗證時，新交易應失敗關閉；
- 充值、提現和交易狀態保留使用者可查記錄，便於核對資金路徑。

## 安全機制不能消除哪些風險？

### 市場和流動性風險

預測市場可能因流動性不足、價差擴大、突發消息或少量交易而快速變動，進而影響指數。

### 模型和資料風險

事件與目標狀態的方向、影響強度或資訊重疊可能被誤判；資料源也可能延遲、中斷或更正。

### 區塊鏈與托管風險

BSC 擁堵、鏈重組、RPC 中斷、代幣合約問題、簽名密鑰風險或托管服務故障，都可能延遲或影響充提。

### 產品可用性風險

交易、提現或新充值地址分配可能在異常時被暫停或延遲。處於鏈上結果不明確狀態的提現會繼續等待確認，不會僅因頁面超時立即退回預留餘額。

### 法律、稅務與地區風險

可參與性、稅務處理和產品法律性取決於所在地和個人情況。文檔中的“1% 開倉費”是產品收費，不是對個人稅務義務的判斷。

::: danger 風險邊界
錢包簽名、多層校驗、分離控制、確認數和帳本對賬能夠降低特定故障的概率或影響，但不代表資金、交易可用性、本金或收益獲得保證。
:::
